## 修复表单项 description 导致输入框不对齐问题

### 问题描述
表单项配置了 `description` 后，输入框位置向上偏移。一行两个字段（col-span-1）时，
有 description 和没有 description 的字段输入框顶部不对齐。

### 根因分析
Vben Form 的 `FormItem`（`packages/@core/ui-kit/form-ui/src/form-render/form-field.vue`）结构：

```
FormItem (flex-row + items-center)   ← label 与右侧内容区垂直居中对齐
  ├── FormLabel
  └── div.flex-auto (右侧内容区)
        ├── input wrapper (FormControl + suffix)
        ├── FormDescription            ← 占据文档流空间，使右侧内容区变高
        └── FormMessage (absolute)     ← 错误消息，绝对定位不占空间
```

- 无 description 的字段：右侧内容区高度 = 输入框高度，label 与输入框垂直居中 ✅
- 有 description 的字段：右侧内容区高度 = 输入框 + description，
  `items-center` 使整个内容区居中，输入框相对位置上移 ❌

### 修复方案
在应用层新增全局样式 `frontend/apps/web-antd/src/styles/form.css`，
让 description 绝对定位（与错误消息 FormMessage 相同的处理方式），脱离文档流：

```css
/* description 的 id 由 useFormField 生成：${useId()}-form-item-description */
[id$='-form-item-description'] {
  position: absolute;
}

/* 校验失败时错误消息与 description 位置重叠，优先展示错误消息 */
.form-valid-error [id$='-form-item-description'] {
  visibility: hidden;
}
```

absolute 不指定 top/left 时元素停留在原静态位置（输入框下方），
FormItem 自带的 `pb-4` 底部 padding 已预留空间，不会与下一行重叠。

### 修改的文件
1. **新建** `frontend/apps/web-antd/src/styles/form.css` - 全局修复样式
2. **修改** `frontend/apps/web-antd/src/bootstrap.ts` - 引入 `./styles/form.css`（放在 @vben/styles 之后）

### 关键知识点
**Vben Form FormItem 内部结构（form-field.vue）：**
- 非垂直模式：`flex-row items-center`，label 固定宽度 + 右侧 flex-auto 内容区
- FormDescription 的 id 格式：`${useId()}-form-item-description`，可用属性选择器定位
- FormMessage 本身就是 `absolute` 定位（静态位置 = 输入框下方），FormItem 的 `pb-4` 为其预留空间
- compact 模式下错误消息走 VbenTooltip，不渲染 absolute FormMessage

## 实现 badgeType 清空时 badgeContent 联动清空并禁用

### 需求
菜单管理表单中，当 `badgeType`（徽标类型）未选择或被清空时，
`badgeContent`（徽标内容）需要自动清空值并禁用输入。

### 实现方案
利用 Vben Form `dependencies` 的三个能力组合（`form-render/dependencies.ts`）：
1. `triggerFields` 加入 `'badgeType'`，监听其变化
2. `disabled: (values) => !values.badgeType` - 动态禁用
3. `trigger: (values, formApi) => {...}` - 回调中通过 `formApi.setFieldValue()` 清空值

```typescript
dependencies: {
  triggerFields: ['type', 'badgeType'],
  show: (values) => values.type !== PermissionTypeOptionsValueAction,
  disabled: (values) => !values.badgeType,
  trigger: (values, formApi) => {
    if (!values.badgeType && values.badgeContent) {
      formApi.setFieldValue('badgeContent', undefined);
    }
  },
}
```

### 关键知识点
**Vben Form dependencies 完整能力（dependencies.ts）：**
- `if` - 不渲染 DOM（优先级最高，为 false 时后续逻辑不执行）
- `show` - 隐藏但保留 DOM
- `disabled` - 动态禁用
- `required` - 动态必填
- `componentProps` - 动态组件属性
- `rules` - 动态校验规则
- `trigger(values, formApi)` - 自定义回调，可操作 formApi（setFieldValue 等）
- 所有回调签名：`(formValues, formApi) => any`，支持 async

## 外链菜单点击不跳转 — 分析与方案

### 问题
菜单类型选 `link`（外链），输入 linkUrl 后点击菜单没有跳转。

### 完整点击链路分析
1. **菜单 UI 点击**：`packages/@core/ui-kit/menu-ui/src/components/menu-item.vue:62-71 handleClick()`
   → 调用 `rootMenu?.handleMenuItemClick?.({ parentPaths, path })` 发出 `select` 事件。
2. **layout 菜单接收**：`packages/effects/layouts/src/basic/menu/menu.vue:22-24 handleMenuSelect`
   → 转发 `select` 事件给上层。
3. **layout 上层处理**：`packages/effects/layouts/src/basic/menu/use-mixed-menu.ts:87-109 handleMenuSelect(key, mode)`
   → 调用 `navigation(key)`。
4. **实际导航**：`packages/effects/layouts/src/basic/menu/use-navigation.ts:40-65 navigation(path)`
   → 判断 `route?.meta?.link` 或 `isHttpUrl(path)` → `openWindow(..., { target: '_blank' })`。

### 根因
`use-navigation.ts` 判断的是 `route.meta.link`（**注意**：不是 `linkUrl`），
这是 Vben 框架约定的元数据字段名（`packages/utils/src/helpers/generate-menus.ts:43` 也读取 `meta.link`）。

而**应用层 access.ts**（`apps/web-antd/src/router/access.ts:78-132 transformAccessRoutes`）
把后端菜单转成路由时，**完全没有把后端 `linkUrl` 写到路由 `meta.link` 上**：

```typescript
const route: any = {
    name: menu.code || menu.name,
    path: menu.path,           // ← 直接用后端 path
    meta: {
        title: $t(menu.title),
        icon: menu.icon,
        order: menu.weight ?? 0,
        badgeType: ..., badge: ..., badgeVariants: ...,
        // ← 缺 link: menu.linkUrl
    },
    component: ...
}
```

而且前端 path 字段对 link 类型应当**留空**或填一个占位符（不能用外链 URL 当 path），
否则路由解析不到 path，`routeMetaMap.get(path)` 会返回 undefined，外链判断直接失效。

### 三种修复方案（按推荐度）

**方案 A（推荐）—— access.ts 中区分 link 类型写入 meta.link**
- `transformAccessRoutes` 中识别 `menu.type === 'link'`
- 当 link 类型时：
  - 不写 path（或写占位 path），component 给一个简单占位
  - `meta.link = menu.linkUrl`
- `navigation()` 的 `route.meta.link` 判断即可命中，调用 `openWindow` 打开新窗口

**方案 B —— access.ts 直接用 linkUrl 覆盖 path**
- `path: menu.type === 'link' ? menu.linkUrl : menu.path`
- `navigation()` 第 51 行已有 `isHttpUrl(path) → openWindow(path, { target: '_blank' })` 的兜底逻辑
- **问题**：path 是 http URL 会污染 useRoute 等所有依赖 route.path 的地方（如 sidebarActive、面包屑、tabs）
- 不推荐

**方案 C —— 在 layout 包的 use-navigation 中扩展判断**
- 在 `shouldOpenInNewWindow` 中检查菜单数据（accessStore）而非仅路由 meta
- 改动范围跨包，影响其他消费者（其他 layout 类型）
- 过度设计，不推荐

### 配套注意点
1. **菜单 path 必填**的表单校验需要为 link 类型豁免（参考 cleanHiddenFields：link 类型隐藏 path）
   - 当前 schema 应当已经处理，需确认 `path` 字段的 `dependencies.show` 对 link 类型为 false
2. **iframe 类型**同理：iframe 的 linkUrl 应使用 `IFrameView` 组件，path 用 `/iframe/...` 占位，
   不应走 `meta.link` 逻辑。这块当前 access.ts 也未特殊处理。
3. **菜单类型 iframe 的处理**（顺手提一下）也需要在 access.ts 中识别 `menu.type === 'iframe'` 时
   设置 `component: IFrameView`，否则当前会走 `getViewComponent(menu.component)` 返回 undefined。
   这一块在 `apps/web-antd/src/views/_core/fallback/` 下应有兜底视图。

### 待用户确认
- 选择方案 A / B / C
- 是否一并处理 iframe 类型（同一文件，顺手改）

## link + iframe 占位逻辑重构为 helper 函数（已完成）

### 改动
**`frontend/apps/web-antd/src/router/access.ts`**

1. 新增 import：`PermissionTypeOptionsValueIframe`（与 `PermissionTypeOptionsValueLink` 一起）
2. 新增 `buildSpecialRoute(menu, type)` helper：
   - 入参：menu 项 + 类型标识 `'link' | 'iframe'`
   - 返回 `{ name, path, meta, component }` 占位路由配置；缺 linkUrl 返回 null
   - 内部 switch 两种类型的差异化配置（占位 prefix、meta 字段、component）
3. `transformAccessRoutes` 中：
   - `isIframe = menu.type === PermissionTypeOptionsValueIframe`
   - `if (isLink || isIframe) { const override = buildSpecialRoute(...); ... }` 统一入口
   - 通过 `Object.assign(route.meta, override.meta)` 应用差异化 meta

### 设计要点
- **占位 path 模式一致**：`/link/${code}` / `/iframe/${code}`，name 加 `Link_` / `Iframe_` 前缀避免冲突
- **缺 linkUrl 兜底**：helper 返回 null 时不应用任何特殊逻辑，菜单项退化为普通未配置状态
- **元数据字段对应关系**：
  - link → `meta.link` + `meta.openInNewWindow: true`（命中 use-navigation 的 openWindow）
  - iframe → `meta.iframeSrc`（命中 content.vue 全局挂载的 IFrameRouterView）
- **component 字段**：
  - link → undefined（不需要 Vue 组件，由新窗口承载）
  - iframe → IFrameView（layoutMap 已注册，组件内本身是空壳，靠全局 IFrameRouterView 渲染 `<iframe :src="meta.iframeSrc">`）

### 复用收益
