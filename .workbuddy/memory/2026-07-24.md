## 后端菜单数据格式转换

### 问题发现
后端返回的 menuTree 格式与 Vben Admin Backend 模式期望的格式不一致：
1. 缺少 meta 对象（icon、name、weight 应在 meta 内）
2. type 值不匹配：menu_dir → 应为 catalog
3. component 路径格式：/menu → 应为相对路径 permission/menu/index
4. 目录类型缺少 component（应设为 BasicLayout）

### 解决方案
在 `router/access.ts` 中添加 `transformMenuTree()` 转换函数：
- 定义 `BackendMenu` 接口匹配后端数据结构
- 自动转换 type: menu_dir → catalog
- 将 icon、name、weight 包装到 meta 对象
- 目录类型自动设置 component 为 BasicLayout
- 去掉 component 路径前导斜杠
- 递归处理 children

## 404 问题排查与修复 (2026-07-25)

### 问题描述
用户登录后进入系统，所有页面都显示 404。

### 根因分析（3 个关键问题）

#### 问题 1: 目录类型 component 为 undefined
**位置**: `access.ts` 第 67-69 行（旧代码）
```typescript
component: menu.type === 'menu_dir'
    ? undefined   // ❌ 目录没有组件！
    : getViewComponent(menu.component),
```
**影响**: 父级路由（如"权限管理"）无组件，导致子路由无法嵌套渲染 → 404

#### 问题 2: 组件路径不匹配
**后端返回**: `/menu`
**转换结果**: `/src/views//menu.vue` (不存在)
**实际位置**: `views/permission/menu/index.vue`
**影响**: 组件加载失败 → undefined → 404

#### 问题 3: 后端字段格式不一致
- 后端返回 `type: "menu_dir"`，接口期望 `"catalog"`
- 后端返回 `parentID`，接口期望 `pid`

### 修复方案 (`router/access.ts` 重写)

1. **目录类型使用 BasicLayout**
   ```typescript
   const isDirectory = menu.type === 'menu_dir' || menu.type === 'catalog'
   component: isDirectory ? BasicLayout : getViewComponent(menu.component)
   ```

2. **组件路径兼容多种格式**
   - 尝试 `${path}.vue`
   - 尝试 `${path}/index.vue`
   - 输出详细错误日志帮助排查

3. **添加完整调试日志**
   - 原始菜单数据
   - 处理后的路由配置
   - 组件匹配结果（✅/❌）
   - 可访问的页面路径列表

### 验证步骤
1. 清空浏览器缓存
2. 打开控制台（F12）
3. 登录系统
4. 查看 `[Access]` 开头的日志：
   - 📁 目录路由应显示 ✅
   - 📄 页面路由应显示 ✅（如果 component 路径正确）
   - ❌ 表示组件路径需要修正
